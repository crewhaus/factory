# CrewHaus v0.8.0 — The Provability Release

**Status:** design draft for review → becomes the RFC issue (`.github/ISSUE_TEMPLATE/rfc.yml`, required here because this is a schema change and an eval-loop change per CONTRIBUTING §3) + a ROADMAP v0.8.x amendment + module briefs in the docs repo (numbers assigned when the docs PR opens; this doc does not pre-assign them).
**Scope:** the `provability:` spec block and its four-rung ladder (`cited` → `grounded` → `checked` → `proven`), the in-loop proof gate that verifies every claim in a harness's answer against evidence before the answer is served, the proof bundle that travels alongside every answer on every surface, the `ProofCheck` family of tools and the pluggable proof checkers behind the `proven` rung, the `@crewhaus/grader-provability` eval layer, and the `crewhaus provability show|check|audit|checkers|prune` command family.
**Feature name vs code token:** the user-facing name is **"provability"**; the code token is **`provability`** everywhere (spec block `provability:`, IR type `IrProvability`, package `@crewhaus/provability`, command `crewhaus provability <action>`, trace event `provability_graded`). The per-answer artifact is a **proof bundle** (`ProofBundle`). The block is deliberately not called `proof:` — `continuity.proof` already means proof-of-*action* on plan steps (design/0.3.0-memory-release.md §2.4); this release's ladder is proof-of-*claim* on answers, and §6.3 says exactly where the two meet.

This design was produced by surveying the tree for every seam the feature touches (file:line citations throughout), and by holding each mechanism to the rule the tree already applies to evidence: `tool-verify` reads its own verdicts literally ("SUPPORTED means the source contains the assertion and nothing more, never that the assertion is true", `packages/tool-verify/src/index.ts:974`), continuity never lets narration produce a ✓ (§2.4 of the 0.3.0 design), and watch-me takes no quality signal from a model's self-claims (design/watch-me.md §2). Provability is those three postures applied to the answer itself.

---

## 0. Why this release, in one paragraph

A CrewHaus harness can already *be checked*: an in-loop `evaluation:` judge scores every completed turn (`packages/runtime-core/src/index.ts:2593`), the research shape writes a numbered `## Citations` block it refuses to omit (`packages/report-writer/src/index.ts:31`), `twelve.answerFaithfulness` audits an answer's sentences against the run's tool results after the fact (`packages/grader-12-metric-rubric/src/faithfulness.ts`), `CitationLint` and `FactCrossCheck` can tell a marker with nothing behind it from a source that does not say what it is cited for (`packages/tool-verify/src/index.ts:622,972`), and 549 deterministic tools exist so that a number in an answer can come from a computation rather than from a model's head. What does not exist is a *requirement*: nothing lets a spec say "an answer from this harness carries proof at this level, and an answer that does not is not served." Every one of those mechanisms is advisory, post-hoc, or confined to one shape. v0.8.0 makes provability a declared property of a harness — one knob, four rungs, a deterministic gate at the same seam the quality judge already uses, and a proof bundle beside every answer so the reader, the eval runner, the console and the audit log all see the same verdict.

### The motivating failures (the release's acceptance tests)

Three scenarios, one per band of the ladder. v0.8.0 is done when each is **un-servable even when the model misbehaves** — deterministic infrastructure first, model discipline second (the 0.3.0 design stance, §1).

**A — the fabricated citation (`grounded`).** A support bot is asked for the refund window and answers "30 days [1]" with `[1]: https://acme.example/policy` — a URL it never fetched, which in fact says 14 days. Today that answer ships; a `twelve.answerFaithfulness` run a week later reports a 0/1 grounding rate nobody reads. At `provability.level: grounded` the gate finds no fetched body behind `[1]` in the session's event log and fails the turn. `on_fail` decides what happens next. Under `retry` (the default) the nudge says so, the model fetches the page, the body does not contain the claim's words, the turn fails again, and once `max_retries` is spent the last attempt is served with a visible ✗ footer. Under `halt` the first failing verdict stops the run, classified `provability`, and nothing is served (on the cli, where the answer streams as it is written, it has already printed; its ✗ footer follows and the run exits 37): like the evaluation gate's `halt`, it does not spend `max_retries` on re-runs first (§5.1). Nothing in that path trusts the model.

**B — the hand-computed total (`checked`).** An invoicing harness reports "the total is 1,284.50". At `checked` the claim must cite `tool:<toolUseId>` of a non-error `MoneyAdd` / `Evaluate` result whose text contains that value, and the gate **re-runs the tool** with the logged input and compares digests. A total the model added up itself has no evidence; a total it computed and then misquoted fails value containment; a tool result it tampered with in prose fails replay.

**C — the overlap claim (`proven`).** A scheduling harness says "no two of the six meetings overlap". At `proven` the sentence must cite `proof:prf_…`, an artifact produced by `ProofCheck`: a certificate the built-in checker verified by cases over the finite set, or an SMT problem Z3 found `unsat` on the negated goal. A false claim yields a counterexample — "meetings 2 and 5 overlap at 10:30" — and that counterexample, not a rationale, is the retry nudge.

## 1. Design stance (three ruling principles)

1. **Evidence is checked, never believed.** Every rung's verifier is deterministic and replayable: citation grammar, source bodies the run itself fetched, tool results the event log recorded verbatim, re-execution of pure tools, and a proof checker's exit status. The model can be wrong about everything and the gate still holds. A model-backed judge exists in exactly one place (§6.2, the paraphrase waiver), is opt-in, spends under `budget.judge_share`, can only *waive one named sub-check*, and leaves a `judgeWaived: true` mark on the binding it touched. It can never raise a rung.
2. **The proof travels with the answer.** Markers inside the text, a proof bundle beside it, on every surface: a footer on the cli, a one-line footer on channel bots, an envelope field on the gateway, a section in the research report, a `provability_graded` line in the trace and the event log, a hash-chained audit record when the sink is wired, and a JSON file under `.crewhaus/proofs/`. There is one bundle shape and every surface renders the same one.
3. **One gate seam, one composition root, absent = byte-identical.** The gate runs where the quality judge already runs (the turn-completion wrapper around `runOneTurn`, `packages/runtime-core/src/index.ts:8512`), it is constructed by one composition root instead of three `renderEvaluation` copies plus an interpreter twin (§4.4), and a spec without `provability:` compiles to the same bytes as today (spread-return-`{}` lowering, the `lowerWatchme` template at `packages/compiler/src/index.ts:4067`). The gate is off until a spec turns it on. The default-on changes the release does make are deliberate and listed in §15 and the CHANGELOG; the largest is the runtime-state floor (§10), on in every harness because the session log it protects is also what `continuity.proof` resolves.

## 2. The ladder

Four rungs above `off`, totally ordered. A spec sets a **floor**; every claim in an answer must bind to evidence whose rung is at or above it. Higher-rung evidence satisfies a lower floor — an execution result satisfies `cited`.

| Rung | The reader can see… | What the gate verifies, deterministically | What it does NOT establish |
|---|---|---|---|
| `cited` | a source behind every claim — "an article reference" | every `[n]` marker in the answer has a `[n]: <source>` definition (the `CitationLint` grammar); the source is a locatable kind (URL, `doi:`, workspace file; free-text bibliographic references only when `sources.bibliographic: true`); the source's host passes `sources.allow` / `sources.deny`; optionally (`sources.resolve: head`) the URL answers a guarded HEAD request | that the source exists beyond its URL, or says anything — a fabricated-but-well-formed reference passes this rung, and the rung's doc says so |
| `grounded` | the claim's words in a source the run actually read | the cited source's **body was fetched in this run** (indexed from the event log's `tool_use`/`tool_result` pairs, §5.2) and the claim's content tokens — or its quoted span, when it quotes — sit inside one window of that body (`FactCrossCheck`'s `checkOneSource`); `grounded.independent: 2` additionally demands two distinct origins per claim | that the source is right; grounding is faithfulness, not truth (`twelve.answerFaithfulness`'s exact posture) |
| `checked` | a computation the harness ran, not recalled | the claim cites `tool:<toolUseId>`; the id resolves in the session logs (child sessions included) to a non-error `tool_result` (`continuity-store`'s `resolveEvidence`, §6.3); the result text contains the claim's values; the tool is on `execution.allow`; when the tool is **pure** and `execution.replay` is on, the gate re-executes it with the logged input and the output digest matches | that the computation was the right one to run — `MoneyAdd` on the wrong column replays perfectly |
| `proven` | a machine-checked proof of the statement | the claim cites `proof:prf_…`; the artifact exists under `.crewhaus/proofs/`, a registered checker accepted it (`ok: true`), its recorded `claim` text covers the answer's sentence, and its assumptions and axioms are listed in the bundle | that the formal statement means what the prose says — the **formalization gap** is shown beside the claim, never hidden (§6.4) |

Two cross-cutting rules:

- **Assumptions are first-class.** A claim may bind to `[A1]: assume: <text>` instead of evidence. Assumptions are excluded from the score's numerator *and* denominator, are **always counted** in the bundle and the footer, are capped by `max_assumptions`, and are graded by `provability.assumptionRate` (§9), so declaring everything an assumption is visible everywhere rather than a way through the gate. `assumptions: forbid` rejects them outright.
- **The score is a fraction, the floor is a threshold.** `score = met / (claims − assumptions)`; the turn passes when `score ≥ threshold` (default `1.0`, every claim) and `assumptions ≤ max_assumptions`. Zero claims is a vacuous pass with a rationale that says so (the faithfulness grader's precedent), because an answer that only asks a clarifying question has nothing to prove.

**The vacuous-pass backstop.** A vacuous pass does not rest on the extractor alone: review rounds found shape after shape that merged a claim into a question or a heading (`30 days [1] — anything else?`, `1,284.60; want the PDF?`, a no-break space, a `<br>`, U+2028, a table row) and served it with a ✓, each fixed shape by shape while the next stayed open. So an answer the extractor finds no claim in passes vacuously only when what a reader sees of it — code, definition lines, URLs and list-item numbers aside — carries **no citation marker and no figure outside a question**. That is read by a segmenter far blunter than the extractor (`provability/src/vacuous.ts`): it cuts at every line break (U+0085, U+2028, U+2029, `\f`, `\v` and `<br>` included), every sentence terminator whether a space follows or not, every semicolon, em or en dash (not one between figures) and table pipe, never at a comma; a stretch ending in `?` is a question from the first segment that opens as one. Each segment that carries a marker, or states a figure and is no question, is a claim verified like any other — "30 days" cut off a trailing "anything else?" is checked against the page and fails where it says 14. A heading is a title to the figure rule except for what it states after a label; a list item's number (`1.`, `2)`, `**1.**`) is the item's, not a figure. A clarifying question with a figure in it, a greeting, a numbered how-to and an answer of code alone stay vacuous.

What counts as a **claim** is decided by one deterministic extractor (§5.1, claim-ledger's `extractClaims`), built from the same sentence splitter, marker grammar and content-token measure the faithfulness graders and `FactCrossCheck` use once §4.1 gives them one owner: a declarative, non-question sentence of the final text that carries a citation marker, states a number, or has at least three content tokens (`MIN_CLAIM_TOKENS`), outside code blocks, not a title heading, not a definition line, not an assumption line. A heading is a title unless it cites a source for a figure or a claim's words (`## The refund window is 30 days [1]`), states a measured value after a label (`## Invoice total: 1,284.50` — a count such as `## Part 2: 5 tips` or a list's label such as `## Step 3: 10 minutes` is a title), or is a sentence stating a figure (`## The invoice total is 1,284.60`, `### No two of the six meetings overlap`), whatever else the answer says or asks; an answer of nothing but headings is read as its headings. The model is told exactly what the gate will see, and can ask (`ProvabilityPreflight`, §7) before it answers.

## 3. Spec surface

The block, on the three `evaluation:`-bearing interactive-loop shapes (cli, channel, managed) and on research (§8.4). A string shorthand sets the floor and takes every default; the object form is `.strict()` throughout so a typo'd key fails the build.

```yaml
provability: grounded          # string shorthand ≡ { level: grounded }

provability:
  level: grounded              # off | cited | grounded | checked | proven   (required in this form; off = inert block)
  on_fail: retry               # retry (default) | halt | note | escalate   (escalate needs agent.model_pool)
  max_retries: 1               # evaluation-style hard cap on gate-triggered re-runs
  threshold: 1.0               # fraction of claims that must meet the floor   (OPTIMIZABLE)
  scope: session               # session (default) | turn — how far back evidence may come from
  assumptions: allow           # allow (default) | forbid
  max_assumptions: 3           # absent = uncapped; assumptions are always counted and rendered
  render: footer               # footer (default) | none | json — how the bundle shows beside the answer

  sources:                     # NOT optimizable — this is an allowlist
    allow: ["*.gov", "arxiv.org", "docs.acme.example"]   # host globs; absent = any public host
    deny: []
    bibliographic: false       # accept un-locatable free-text references at `cited`
    resolve: off               # off (default) | head — reachability check at gate time, HEAD only, guarded

  grounded:
    coverage: 0.8              # per-claim content-token coverage inside one window   (OPTIMIZABLE)
    window_tokens: 60          # how far apart the claim's words may sit in the source (OPTIMIZABLE)
    independent: 1             # distinct origins (eTLD+1 or distinct files) per claim; 2 = corroborated

  execution:                   # the `checked` rung
    allow: [all-compute, all-verify, -goldenUpdate]   # tool-category grammar (0.7.0), expanded at lower time; no bash, no destructive tool (§6.3)
    replay: true               # re-run pure tools with the logged input and compare digests
    max_replays: 20            # per turn

  formal:                      # the `proven` rung
    checkers: [builtin, smt]   # builtin | smt | lean4 — order is the preference told to the model
    # image: <name>            # optional lean4 image override (e.g. a Mathlib-equipped lean image); omit for the curated one
    forbid: [sorry, axiom, native_decide]   # lean pre-scan; smt forbids nothing (its input is data)
    timeout_ms: 30000

  judge:                       # optional model waiver for paraphrase misses at `grounded`; absent = zero model spend
    model: $cheap              # $profile or model id; metered as role "judge" under budget.judge_share
```

Parse-time invariants (the `evaluation:` precedent at `packages/spec/src/index.ts:4541`): `on_fail: escalate` without `agent.model_pool` is a parse error with the same wording; `judge.model` resolving to the agent's own serving model trips the existing judge-independence lint (`allow_self_judge` waives it); `level: off` with any other key set is accepted and the compiler emits an "inert block" warning rather than silently dropping config. `crossFieldIssues()` (`packages/spec/src/index.ts:3805`, append-only ordering preserved) gains the block's genuine contradictions only: the `escalate`-without-pool error above, and a `judge.model` naming an undeclared `$profile`. Two softer findings are `crewhaus lint` rules (§11) rather than parse errors, because each describes a valid spec that is unlikely to do what its author meant, and a parse error would refuse it outright: `level ≥ grounded` on a spec whose `tools:` expand to nothing that can read a source (no fetch, read, retrieve or MCP capability — the model could never ground a claim; `provability-no-source-tool`), and `formal.checkers` naming only sandbox checkers (`smt`, `lean4`) without `builtin` (`provability-sandbox-only-checkers`; the lowering appends `builtin` to the list in any case, so the gate can always check a certificate).

Also carried, **declared and warned**, on crew: the lowering accepts the block and emits the sanctioned `accepted-but-unwired` CompileWarning (the `watchme`-on-managed convention, `packages/compiler/src/index.ts:380-388`); the crew orchestrator's synthesis turn is a named deferred seam (§12). Deliberately NOT on graph, workflow, pipeline, batch, voice, browser, eval, onchain, onchain-game: the strict union rejects the key loudly, which beats dead config. Pipeline is the one that hurts — grounded answers over retrieved chunks is the RAG use case — and §12 names the exact seam.

## 4. Compiler and composition (Pillar 1)

### 4.1 `@crewhaus/claim-ledger` — one owner for the text layer (substrate, behaviour-neutral)

Three packages today carry their own copy of the same heuristics: `tool-verify/src/lib/markdown.ts` (the citation marker and definition grammar, sentence splitting, `citedClaims`), `grader-12-metric-rubric/src/faithfulness.ts` (claim extraction, content tokens, coverage — inlined "byte-for-byte" from `grader-continuity` with a comment saying the dependency edge could not be declared in that PR phase, lines 36–42), and `grader-continuity/src/heuristics.ts` (the originals). The citation-grammar comment in tool-verify already states the rule this release enforces: "two copies of this drift, and then one tool checks a claim the other never saw" (`markdown.ts:143-148`).

`@crewhaus/claim-ledger` is a dependency-free package (the `tool-categories` / `qr-code` discipline) that owns: `splitSentences`, `claimSentences`, `contentTokens`, `coverage`, `CITATION_MARKER` / `DEFINITION` / `lintCitations` / `citationDefinitions` / `citedClaims`, number normalization (`1,284.50` ≡ `1284.5` for value containment), and the **evidence-ref grammar** — the one addition to the definition line's free text: a definition whose source starts with a scheme prefix is an evidence reference, not a source:

```
[1]: https://acme.example/policy        source   (cited; grounded when fetched this run)
[2]: ./docs/pricing.md#refunds          source   (workspace file)
[3]: doi:10.1000/xyz123                 source   (resolved through doi.org when resolve: head)
[4]: tool:toolu_01H…                    execution evidence (checked)
[5]: proof:prf_3f9a…                    formal artifact (proven)
[A1]: assume: the fiscal year starts in April   assumption
```

The grammar is backward compatible: `CitationLint` today treats the whole rest of the line as the source (`markdown.ts:157-160`), so every existing document parses as before and the new prefixes are simply sources it could not locate. `tool-verify`, `grader-12-metric-rubric` and `grader-continuity` switch to importing claim-ledger with no behaviour change apart from the fold (claim-ledger's `foldTypography`, which the gate reads through: `FactCrossCheck` now compares through it too, so a lookalike spelling can change its verdict; §15), pinned by their existing tests; the `doctor --philosophy-alignment` audit gains a grep guard that the marker regex has exactly one definition in the tree (§10).

### 4.3 Lowering

`lowerProvability(spec, ctx): { provability?: IrProvability }` in `packages/compiler/src/index.ts` beside `lowerWatchme` (:4067), spread-return-`{}`: an absent block or `level: off` spreads nothing, so provability-less specs compile byte-identically (pinned by the smoke byte-diff for every fixture under `packages/smoke-harness/src/fixtures/`). Lower-time work: expand `execution.allow` through `@crewhaus/tool-categories` (the compiler already imports it for `tools:`); resolve `escalateTo` with the cascade helper `IrEvaluation` uses; resolve the judge slot; fold the per-shape carriage table (`packages/compiler/src/index.ts:360-400`) with the crew row. `crewhaus compile --strict` additionally refuses `level: checked` when `execution.allow` expands to a tool the catalog cannot resolve offline (the FR-002 posture for unresolvable sinks).

### 4.4 `@crewhaus/evaluation-service` — the composition root the gate needs (and the judge should have had)

The in-loop grader is constructed in **four places that must agree**: `renderEvaluation` in `target-cli` (`src/index.ts:1030`), `target-channel-bot` (:451), `target-managed` (:445), and the interpreter's `buildRunEvaluation` in `apps/cli/src/loop-contract.ts:259` — the loop-contract file itself calls them "the three `renderEvaluation` copies". That is the N-copies-of-codegen pattern 0.3.0 retired for memory (`wireMemory`) and 0.6.0 retired for routing (`wireModels`), and the 0.6.0 rule applies verbatim here: every new in-loop gate lands in one composition root, never in an emitter's codegen.

`@crewhaus/evaluation-service` exports `wireEvaluation(fragment, deps): Promise<{ evaluation?: RunEvaluation; provability?: RunProvability }>` where the fragment is `{ evaluation?: IrEvaluation; provability?: IrProvability; primaryModel }` and `deps` carries the catalog, cwd, session-log root, sandbox factory and the bus. The three emitters collapse to one rendered line (`const __gates = await wireEvaluation(FRAGMENT, { catalog: defaultCatalog, cwd: process.cwd(), … })`) and `loop-contract.ts` calls the same function. Honest compatibility note: bundles **without** `evaluation:` or `provability:` stay byte-identical; bundles **with** `evaluation:` change bytes (one call instead of an inlined grader) with identical behaviour, pinned by the existing `evaluation.test.ts` / `judge-metering.test.ts` suites run against the new emit rather than by byte-diff. runtime-core stays dependency-free: it receives closures (`RunEvaluation`, `RunProvability`) exactly as it receives `opts.memory` and `opts.continuity`.

## 5. The gate at runtime

### 5.1 Seam

`RunChatLoopOptions.provability?: RunProvability`, evaluated inside the same turn-completion wrapper as `opts.evaluation` (`packages/runtime-core/src/index.ts:8512-8700`) — after the tool inner-loop reaches Done, never on an intermediate iteration, on both the `singleTurn` and REPL paths:

```ts
export type RunProvability = {
  readonly level: IrProvabilityLevel;
  readonly onFail: "retry" | "halt" | "note" | "escalate";
  readonly maxRetries: number;
  readonly threshold: number;
  readonly escalateTo?: string;
  /** The verifier — INJECTED by evaluation-service, deterministic, replayable. It receives the same
   *  EvaluationTurn the judge receives (runtime-core/src/index.ts:1082) plus a session-scoped
   *  EvidenceIndex the composition root built from the event log. */
  readonly verify: (turn: EvaluationTurn, evidence: EvidenceIndex) => Promise<ProofBundle>;
  /** Shape-specific rendering of the bundle beside the answer (footer line / JSON); absent = none. */
  readonly render?: (bundle: ProofBundle) => string;
  /** Persist the bundle (`.crewhaus/proofs/…`, tenant-fenced on managed). */
  readonly persist?: (bundle: ProofBundle) => Promise<void>;
};
```

Ordering when both gates are declared: **provability first** (it is free and deterministic), then `evaluation` (which may spend). A failing provability verdict applies its own `onFail`; a retry re-runs the turn and re-grades *both* gates; each gate keeps its own `maxRetries`; `halt` from either is terminal at that gate's first failing verdict, with no re-run first, as `evaluation.on_fail: halt` always was (`run_failed` class `"provability"`, a new `EXIT_CODES.provability` in the 3x "CrewHaus-configured stop" band beside `evaluation: 35`, `packages/errors/src/index.ts:214`); `escalate` shares the cascade (`resolveCascade`, :8558) and its `max_escalations`. A verifier that **throws** is grading-infrastructure failure, not a verdict: logged, fail-open, exactly the judge's contract (:1183-1192) — a broken sandbox must not kill a healthy run; the bundle then records `verdict: "unverified"` and the footer says so rather than printing a ✓.

The retry nudge is composed by the runtime from the bundle — the unmet claims (the model's own sentences), the evidence identifier each cited, and the reason (provability's `UnmetReason`, one stable token per check: `no_citation`, `no_definition`, `not_locatable`, `host_denied`, `private_address`, `path_outside_workspace`, `path_missing`, `unresolved`, `not_fetched`, `not_found_in_source`, `polarity_conflict`, `not_independent`, `tool_missing`, `tool_errored`, `tool_not_allowed`, `value_absent`, `replay_mismatch`, `proof_missing`, `proof_rejected`, `claim_mismatch`, `assumption_forbidden`, `below_floor`) — and ends with the standing instruction to run `ProvabilityPreflight` on the next draft. It contains **no fetched content** and no judge prose, so it crosses no trust boundary; the one model-generated text that can enter the nudge is the optional judge's rationale, which goes through `admitGraderText` at TrustOrigin `consult` like the quality judge's (:8650).

### 5.2 The evidence index

Grounding needs the bodies the run read. They are already persisted: the event log records every `tool_use` (full input) and `tool_result` (full output, `isError`) verbatim — the fact the 0.3.0 proof ladder was built on (§2.4 there). `EvidenceIndex` is built by evaluation-service from the session log (plus child-session logs via the `sub_agent_start/end` brackets, the walk `resolveEvidence` already performs), never from `messages`: compaction may have evicted a fetch from the conversation, but it cannot evict it from the log, so `scope: session` keeps working after a compaction. `scope: turn` indexes only the current turn's tool calls.

Index keys: for every tool call whose input carries a URL-shaped or path-shaped argument (`WebFetch.url`, `Fetch.url`, `Read`'s path, `Retrieve` hits' `url`/`source`, MCP results carrying a `url` field) → `{ toolUseId, origin, sha256(body), body }`. URLs are normalized (scheme, host, path; no fragment; trailing-slash folded) and indexed under both the requested URL and the final URL the fetch header reports (`tool-web` prints `URL: … Status: …` as the first line of every result, `packages/tool-web/src/index.ts:569`), so a citation of a pre-redirect URL still grounds. `WebFetch` never calls a model — a `prompt` is prepended to the page's markdown, not used to summarise it (`tool-web/src/index.ts:25-29`) — so a fetched body is the page, which is why it is admissible as grounding evidence at all. Bodies that reached the context through an MCP server are evidence too; they were classified at the `mcp` origin when they arrived and the gate adds no second pass (AGENTS.md Pillar 3 rule 6).

### 5.3 The proof bundle

One shape, every surface:

```ts
export type ProofBundle = {
  readonly version: 1;
  readonly level: IrProvabilityLevel;           // the floor
  readonly verdict: "pass" | "fail" | "unverified";
  readonly score: number;                       // met / (claims − assumptions)
  readonly achieved: IrProvabilityLevel | "none"; // the highest floor this answer would have passed
  readonly claims: ReadonlyArray<{
    readonly index: number; readonly text: string; readonly line?: number;
    readonly status: "met" | "unmet" | "assumption";
    readonly bindings: ReadonlyArray<{
      readonly ref: string;                     // "[1]" / "[A1]"
      readonly kind: "source" | "excerpt" | "execution" | "formal" | "assumption";
      readonly rung: IrProvabilityLevel | "none";
      readonly ok: boolean; readonly reason?: string;
      readonly origin?: string;                 // normalized URL / path / toolUseId / prf_ id
      readonly sha256?: string;                 // body or result digest the verdict was made against
      readonly excerpt?: string;                // ≤240 chars, whitespace-collapsed — the FrozenProof discipline
      readonly replayed?: boolean; readonly judgeWaived?: boolean;
    }>;
  }>;
  readonly assumptions: number; readonly unmet: number; readonly retryIndex: number;
  readonly checkers?: ReadonlyArray<{ readonly id: string; readonly artifact: string; readonly axioms: readonly string[] }>;
  readonly spentUsdMicros?: number;             // the waiver judge, when any
  readonly bundleHash: string;                  // sha256 over the canonical JSON, for the audit record
};
```

Excerpts are frozen into the bundle for the same reason `FrozenProof` freezes a result digest (`packages/continuity-store/src/evidence.ts:45`): session transcripts are TTL-evicted at 30 days, and a bundle must stay human-checkable after the body it was checked against is gone. Bundles live at `.crewhaus/proofs/<spec>/<sessionId>/turn-<n>.json` — a retried turn keeps every pass, its k-th at `turn-<n>.<k>.json`, and the last is the turn's standing bundle — (mode 0600, tenant-fenced on managed by the tenancy path rules session-store enforces), are covered by `crewhaus state backup/restore` like every `.crewhaus/` subdir — except on the managed shape, where each turn runs under its tenant and the bundles live under `<CREWHAUS_TENANTS_ROOT>/<tenant>/proofs/<spec>/` (default root `/tmp/crewhaus-tenants`), outside the `.crewhaus/` directory `state backup` archives, so an operator backs that root up on its own — carry no TTL (they are the audit artifact; `crewhaus provability prune` manages size), and the trace/event-log line `provability_graded` carries the summary (`level, verdict, score, achieved, claims, unmet, assumptions, retryIndex, bundleHash, judgeModel?, judgeCostUsdMicros?, escalatedTo?`) rather than the whole bundle. When the justification audit sink is wired (`runChatLoop({ justificationAuditSink })`), a hash-chained `provability_evaluated` record with the same summary is appended to `@crewhaus/audit-log` beside `permission_justification_evaluated`.

### 5.4 Rendering beside the answer

- **cli** (`render: footer`, default): the markdown renderer (`packages/runtime-core/src/cli-markdown.ts`) prints one line after the answer — `── provability · grounded ✓ · 6/6 claims · 3 sources · 0 assumptions · .crewhaus/proofs/support-bot/sess_…/turn-7.json`; on a failing `note` verdict the line reads `✗ 4/6 · unmet: [2] [5]`. `render: json` prints the bundle; `none` prints nothing (the trace line still fires). The cli streams every attempt as it is written — the REPL, and `crewhaus run --prompt`, whose footer rides the printed result — so a rejected attempt gets its ✗ under it before the re-run, a claimless final message ("Done.") has the turn's printed text graded in its place (narration of what the agent is about to do, and an attempt already rejected, left out), and under `halt` the unproven answer has printed before its ✗ footer and the classified stop (exit 37).
- **channel**: the same single line appended to the outbound reply by the generated `runTurn` in `target-channel-bot` (the place the boot-time env stamps and the reply formatting already live), honouring `render: none` for teams that find it noisy.
- **managed / gateway**: `RunsCreateResult` and `RunsContinueResult` (`packages/gateway-protocol/src/index.ts:89,105`) gain an optional `proof: ProofBundle` field (additive, `.optional()`, protocol version unchanged), and SSE subscribers receive `provability_graded` like every other bus event.
- **research**: the report's JSON gains `proof` and the markdown gains a `## Provability` section after `## Citations`, emitted unconditionally when the block is on (the `NO_CITATIONS_NOTICE` posture: an ungated report never passes for a gated one).

## 6. The verifiers, rung by rung

All four live in `@crewhaus/provability` as pure functions over `(text, EvidenceIndex, config)`; the gate, the `ProvabilityPreflight` tool, `crewhaus provability check` and the research report gate call the **same** `verifyDocument`. The package imports no model adapter — the `doctor` audit checks that (§10).

### 6.1 `cited`

`lintCitations` + `citationDefinitions` from claim-ledger over the final text; every marker in a claim sentence must be defined; each definition is classified by the evidence-ref grammar. Sources: `https?:` URLs and `doi:` pass the `sources.allow` / `deny` host globs (deny wins; absent allow = any public host; the private-address classifier that 0.7.0 unified across ten copies rejects loopback/RFC1918/link-local hosts here too — a citation of `http://169.254.169.254/` is not a source); workspace paths must resolve inside the workspace (the `resolveSafe` containment `FactCrossCheck` uses) and exist; free-text references are accepted only under `sources.bibliographic: true`. `sources.resolve: head` issues one HEAD per distinct URL per session through `tool-fetch`'s guarded fetch (SSRF classifier, redirect re-check, timeout), caches the status, and treats anything but 2xx/3xx as `unresolved`. No body is read, so nothing enters the context and no boundary classification is needed; the request is still an egress and is recorded as one (`egress_decision`, sink `provability.resolve`).

### 6.2 `grounded`

For each claim and each source binding: look the normalized origin up in the EvidenceIndex; absent → `not_fetched`. Present → `checkOneSource` (the FactCrossCheck kernel, moved to claim-ledger): quote mode when the claim carries a quoted span of ≥ 4 tokens (strictest — the span must appear verbatim), paraphrase mode otherwise (content-token coverage ≥ `grounded.coverage` inside a `window_tokens` window). `independent: n` requires n distinct origins (eTLD+1 for URLs, distinct files for paths) with an `ok` binding. Polarity conflicts (the source contains the words plus a negation the claim lacks) are reported as `polarity_conflict`, FactCrossCheck's existing verdict.

**The waiver judge** (`provability.judge`, opt-in): when a binding fails *only* on paraphrase coverage (the body was fetched, the claim's words were partly found), the judge is asked — sentinel-wrapped `buildJudgePrompt`, forced-tool structured output, temperature 0, metered as `role: "judge"` under `budget.judge_share`, exactly the eval-judge contract — whether the excerpt supports the claim. A `yes` flips that binding to `ok` with `judgeWaived: true`; it cannot touch any other reason, cannot touch `cited`/`checked`/`proven` bindings, and the footer renders waived counts separately (`6/6 claims (1 judge-waived)`). Past the judge share the waiver is skipped, not guessed.

### 6.3 `checked` — where the two ladders meet

`tool:<toolUseId>` bindings resolve through `continuity-store`'s `resolveEvidence` (`packages/continuity-store/src/evidence.ts`), the same function `PlanComplete` uses for the proven transition on plan steps (`packages/tool-plan/src/index.ts:454`): the id must exist in the session logs (child sessions included) with a non-error result. On top: the tool name must be on the lowered `execution.allow`; the claim's normalized numerals and quoted tokens must appear in the result text (`value_absent` otherwise); and when the catalog marks the tool **pure** (`readOnly && concurrencySafe`, the safety flags `tool-text` pins package-wide) and `execution.replay` is on, the gate re-executes the tool through the catalog with the logged input (bounded by `max_replays`) and compares `sha256` of the normalized output — `replay_mismatch` on disagreement. `Bash`, `Python` and every `destructive` or `sideEffect` tool are excluded from the default allowlist and never replayed; a spec that lists them opts into "it ran" without "it reproduces", and the binding records `replayed: false` so the bundle is honest about the difference. `continuity.proof: require`'s long-deferred enforcement (`packages/memory-service/src/index.ts:944-952` still prints the boot note) lands in the same PR, because the proof-mode seam it was waiting for is this one: `require` now refuses `PlanComplete` below `proven` through the same resolver, and `off` skips verification.

### 6.4 `proven`

`proof:prf_…` bindings resolve to an artifact `ProofCheck` wrote under `.crewhaus/proofs/<spec>/artifacts/<id>.json`: `{ id, checker, claim, statement, proof, ok, assumptions[], axioms[], outputDigest, checkedAt }`. The gate requires `ok: true`, and that the answer's claim sentence covers the artifact's recorded `claim` (the grounded coverage test, so an unrelated proof cannot be attached to a sentence). The bundle lists the checker, the formal `statement` beside the prose, and every assumption and axiom the proof depends on. The correspondence between prose and formal statement — the formalization gap — is the one thing no deterministic gate can verify; the design shows it rather than hides it: the bundle carries the formal statement beside the prose, and every surface renders both. No model is asked whether the two correspond: the waiver judge runs only on a paraphrase miss at `grounded` (§6.2), and a correspondence opinion is not part of 0.8.0.

`@crewhaus/proof-checker` defines `ProofChecker { id, available(): Promise<boolean>, check(input): Promise<CheckResult> }` and ships three:

- **`builtin`** — a dependency-free **certificate checker** for a small language, always available, no Docker: exact bigint rationals; equalities and inequalities over arithmetic terms with variables; propositional connectives; bounded quantifiers over explicit finite domains. A certificate is a numbered list of steps, each `{ stmt, by, from }` with `by` one of `given` (becomes an assumption), `arith` (both sides normalize to the same exact value, ground terms only), `subst`, `mp`, `and_intro` / `and_elim`, `or_intro`, `cases` (over a disjunction or a finite domain), `contra`, `instantiate` (∀-elim with an explicit witness), `witness` (∃-intro). No induction and no unbounded quantification — those need `smt` or `lean4`, and the checker says so in its refusal. The verifier is small enough to read in one sitting, which is the point: the model does the searching, the checker only checks.
- **`smt`** — SMT-LIB 2 to Z3 in a curated sandbox image (`@crewhaus/sandbox-image-z3`, registered through `@crewhaus/sandbox-image-registry` exactly like `sandbox-image-go`). The image is built from `packages/sandbox-image-z3/Dockerfile` (the official Z3 release binary, sha256-checked, on a distroless base) and pushed to `ghcr.io/crewhaus/sandbox-z3` by the release workflow's `sandbox-images` job; `docker-images` builds target shapes only, and its digest recorder rejects anything else. The artifact asserts the hypotheses and the **negated** goal; `unsat` ⇒ proven, `sat` ⇒ the model Z3 returns is the counterexample in the retry nudge, `unknown` / timeout ⇒ `proof_rejected`. Hypotheses are assumptions in the bundle. Linear and non-linear arithmetic, bit-vectors, arrays, finite domains.
- **`lean4`** — a curated, Mathlib-free Lean 4 image (`@crewhaus/sandbox-image-lean4`, built from its package's Dockerfile out of the official Lean release and pushed to `ghcr.io/crewhaus/sandbox-lean4` by the same `sandbox-images` job); `formal.image` points at a Mathlib-equipped image for specs that need it. A deterministic pre-scan refuses the `formal.forbid` tokens (`sorry`, `axiom`, `native_decide` by default); the checker runs the file and `#print axioms` on the theorem, and anything beyond the standard three (`propext`, `Classical.choice`, `Quot.sound`) is recorded as an axiom in the bundle.

Both sandbox checkers run with `network=none`, read-only root and the `formal.timeout_ms` budget, and each refuses to run on a harness with no container sandbox or on the `noop` backend (`packages/proof-checker/src/sandbox-common.ts`), the posture `tool-code-execution` takes (`packages/tool-code-execution/src/index.ts:223`). The floor is per checker, not per tool: `ProofCheck` is not `requiresSandbox`, because the builtin checker needs no sandbox and a tool-level flag would deny it on every sandbox-less harness (§7). Proof text is model output that may have absorbed injected content; it is program text executed by a checker; the sandbox is mandatory, and the builtin checker is a parser, not an interpreter of anything.

### 9.1 `@crewhaus/grader-provability`

Registered like `continuity.*` and `twelve.*`, thresholds declared beside them, all deterministic over the bundle the runner finds in `RunResult.artifacts.proof` (a new optional field on `RunArtifacts`; the eval runner persists the gate's bundle per sample):

| Grader | Measures | Threshold |
|---|---|---|
| `provability.claimCoverage` | met / (claims − assumptions) at the declared floor | ≥ 0.95 |
| `provability.rungAchieved` | the highest floor the answer would have passed, run at every rung (0..4, normalized) — a per-sample ladder score that shows *how far* an answer falls short, not just that it does | ≥ declared level |
| `provability.citationValidity` | defined markers / markers (the `cited` sub-check alone) | ≥ 0.99 |
| `provability.assumptionRate` | assumptions / claims — makes the assumption dodge visible | ≤ 0.1 |
| `provability.replayIntegrity` | replayed executions whose digest matched / replayed | = 1.0 |

### 9.2 OPTIMIZABLE_PATHS (`packages/spec-patch/src/index.ts:610`)

## 10. Security (Pillar 3) — no new trust origin, one new floor

The feature **ingests nothing new**. Source bodies enter through tools that are already classified at `tool` / `mcp` / `subagent` origins and lineage-tagged; the gate reads them from the event log afterwards and adds no second classification pass. The retry nudge is runtime-composed from the model's own sentences and evidence identifiers. The waiver judge's rationale is the only model text that can reach the transcript from this feature and it goes through `admitGraderText` at `consult`, like the quality judge's. So: **no new `TrustOrigin`**, stated rather than overlooked.

What the feature adds on the sink side and the execution side:

- **The runtime-state floor, on in every harness** (a deliberate default-on change, §15). Evidence is checked only while the agent cannot write it: a `Write` that appends a hand-made fetch to the session log would ground any text under any URL. Every run computes its state roots (runtime-core `runtimeStateRoots`: the session logs, the spilled tool results, the proof bundles) and permission-engine denies a call that is not read-only and names a path inside one before any rule is read (`EvaluateOptions.protectedRoots`), and one that acts on everything beneath a workspace directory holding one (an operative field declared `beneath`: `StateImport` or `StoreMigrate` given `.crewhaus`); only `bypass`, which consults nothing, skips it. The floor reads where a call WRITES: a field the tool only reads from (`source`, `relocates`, and `reads` — CopyPath's and ArchiveCreate's `source`, ArchiveExtract's `archive`, an importer's `file`) is left out, so a backup of `.crewhaus` runs and a move of it does not. `CopyPath`, `MovePath`, `RemovePath`, `ArchiveExtract`, `GitApplyPatch`, `StateImport` and `StoreMigrate` write beneath a directory they name, where the floor cannot see the target, so each checks its own targets against the same roots on the bridge (`RuntimeBridge.protectedRoots`) and refuses in every mode, `bypass` included; `GitApplyPatch` also refuses a patch whose file list is too long to check, and `StateImport` an import whose `stateDir` is the workspace root and whose entries reach a root. The floor does not wait for `provability:` because `continuity.proof` resolves against the same session log in every mode, the default `ladder` included. Residual, documented rather than closed: `Bash` and `RunCommand`, whose writes no layer can see; closing it needs keyed integrity on the log lines (a MAC keyed outside the tree the agent can write).
- `sources.resolve: head` is an egress (`scope: external`) and runs through the one guarded fetch, HEAD only, one per distinct URL per session, recorded as an `egress_decision`.
- `ProofCheck` with `smt` / `lean4` executes untrusted proof text in the sandbox under the existing floor; `builtin` parses and never executes. The lean pre-scan is deterministic and runs before the container does.
- Replay re-executes **pure** tools only, from the catalog, with the logged input; nothing replayed can reach a network or a filesystem write by the same safety flags that define purity.
- `execution.allow` and `sources.allow/deny` are allowlists and are not optimizable.
- Gaming is tabulated, not assumed away: a fabricated well-formed URL passes `cited` (documented); a real-but-irrelevant source fails `grounded` on coverage; a real-but-irrelevant tool result fails `checked` on value containment; a proof of the wrong theorem fails `claim_mismatch`; the assumption dodge is counted on every surface and graded. The residual — a model that fetches a page it wrote itself, or proves a trivial restatement — is exactly what `provability.audit`'s gaming signals (§11) and the eval graders exist to surface, and the design says so instead of claiming a closed loop. A self-written source still grounds (an agent that sets a value and reports it reports the truth), but the binding names the earlier call that wrote the claim's words to that file or URL (`writtenBy`, followed back through copies and moves), the bundle counts it (`selfWritten`), the footer shows it beside the sources, and `provability.claimCoverage` names it and does not count it toward a sample's `expected_sources`.

  Self-authorship is decided **per origin**: the calls that wrote into the places a body was read from, before it was read, are asked whether the claim at its tightest in the span that grounded it is text they put there — a string they sent holds it whole, a line they added overlaps where it stands in the body with a word they introduced (an `Edit` of `14` to `30`; an unrelated line appended beside it is not), or a text they put there whole lies inside it (an `Edit` that took a `not` out). A read made before any writer that grounds the claim grounds it unmarked. MCP readers are marked like the builtin ones: an MCP call's origin is a field its declared schema lists — the gate reads the schemas from its own catalog, then `defaultCatalog` — and where no schema is known an input that carries anything else a call could have been pointed at names nothing, so a stray `url` beside a `paths` list or a `command` grounds no page nobody fetched; a row an MCP server stored from the run's own text is refused, not marked. **FactCrossCheck over self-written text** is no check: where every file it found the claim in is one the run wrote it into first, the execution binding reaches a marked `grounded` at most (the file itself, cited, does no better), and `provability audit` lists it with the self-written sources. **A copy of a state root is refused**: a session log copied, moved, concatenated or unpacked into the workspace (followed back through up to four copy or move steps, a directory copy mapping each file beneath it) holds every answer verbatim, the refused one among them, so nothing read from it, cited or checked, is a source.

  What stays open: text written by `Bash` or `RunCommand` (a command line names no place the gate can read), or by an earlier session; a write that names the place in a form the gate cannot map to the cited one (a repository path behind a raw-file URL); text an earlier turn wrote when a caller hands the verifier a turn-only index rather than the session's with `turnNumbers` (the gate and its preflight hand the latter); an MCP tool with no known schema handed a url as its only address; and, past the grounding budget, nothing is marked.

`doctor --philosophy-alignment` (`apps/cli/src/index.ts:7322`) gains three findings: the citation-marker regex has exactly one definition in the tree (claim-ledger); `@crewhaus/provability` imports no model adapter package; `provability.level` is absent from `OPTIMIZABLE_PATHS`.

## 15. Compatibility

- Old specs parse unchanged; the block is optional and `level: off` lowers to nothing. Spec schema stays `version: 2` — no migration, `crewhaus upgrade` is a no-op for this release.
- Bundles without `evaluation:` or `provability:` recompile byte-identically (smoke byte-diff over every fixture). Bundles with `evaluation:` change form (one `wireEvaluation` call) with identical behaviour — called out in the CHANGELOG as the release's one codegen-shape change.
- The claim-ledger hoist is byte-for-byte the same heuristics apart from the fold; `twelve.*` and `continuity.*` verdicts do not move.
- `FactCrossCheck` compares a claim and its source through the gate's fold (`foldTypography`) in every harness that grants it, `provability:` or not. A digit of any script, a fullwidth or mathematical letter or digit, a superscript number, a Cyrillic or Greek lookalike inside a Latin word, a soft hyphen or zero-width character and a footnote mark on the claim are read as the plain spelling, so a 0.7.x `notFound` can become `supported` and a hidden or lookalike `not` a `polarityConflict`. ASCII-only text is checked as before; the excerpt stays the source's own text. Named in the CHANGELOG under changes that affect a harness without `provability:`, and guarded by `scripts/default-on-changes.test.ts`.
- `continuity.proof: require | off` starts being enforced (PR 6). Today both degrade to the ladder with a boot note; a spec that set `require` and relied on the degrade will now see `PlanComplete` refuse unproven completions — the behaviour the 0.3.0 design promised and `init` templates asked for. Headline CHANGELOG entry.
- Additive protocol: `RunsCreateResult` / `RunsContinueResult.proof` optional; `provability_graded` / `proof_checked` are additive event kinds (event-log readers skip unknown kinds by design).
- `.crewhaus/proofs/` is a new state dir, covered by `state backup/restore` automatically. On managed, bundles live under `<CREWHAUS_TENANTS_ROOT>/<tenant>/proofs/<spec>/` (default `/tmp/crewhaus-tenants`) and are **not** carried by `state backup`; back up the tenants root separately.
- In every `continuity.proof` mode (the default `ladder` included), a plan or goal title and a goal unit are stored on one line — a newline collapses to a space, so a model-written title can no longer print a forged `[proven]` step — and are capped at 512 and 64 characters. `PlanUpdate`, `GoalWrite` and `GoalUpdate` refuse a longer one, and `GoalUpdate` a blank title, so the default mode can refuse input 0.7.x accepted.
- The runtime-state floor (§10) is on in every harness: the agent's tools cannot write the session logs, the spilled tool results or the proof bundles, whatever a rule says, nor act on everything beneath a directory holding one (`StateImport` or `StoreMigrate` given `.crewhaus`). Reading from them is not a write: a copy or an archive of `.crewhaus` runs as in 0.7.x. `bypass` lifts the permission-level floor only; `CopyPath`, `MovePath`, `RemovePath`, `ArchiveExtract`, `GitApplyPatch`, `StateImport` and `StoreMigrate` refuse in every mode, and `Bash` / `RunCommand` are the residual. In the CHANGELOG under changes that affect a harness without `provability:`.
- `WebFetch`'s header names the page it served (§5.2): after a redirect `URL:` is the final address and a `Requested:` line gives the one asked for. A fetch that is not redirected prints the 0.7.x header.
- `compile --emit-as cf-worker`, local and hosted, warns `accepted-but-unwired` for `evaluation:`, which the edge never ran, and reports the spec and lowering warnings the local compile gives. The CLI's `--strict` fails on them; the hosted compile returns them beside the bundle.

## 16. Alternatives considered

- **A `grader.type: provability` inside `evaluation:`.** Rejected: provability is a *policy* ("answers carry proof at this level") and evaluation is a *quality* judgement; a spec wants both, each with its own `on_fail`, and a deterministic gate should run before a judge that spends. They share the seam and the composition root, not the block.
- **An LLM judge as the groundedness oracle.** Rejected as the mechanism, kept as a bounded waiver: a judge can be talked into a verdict by the content it reads, costs money per turn, and would make "proof" mean "a model agreed". Deterministic coverage over bodies the run fetched is replayable and cannot be argued with; the waiver exists only for the paraphrase miss, is opt-in, and leaves a mark.
- **Structured `Claim` / `Cite` tool calls instead of inline markers.** Rejected: proof that lives in tool calls is invisible to the reader, and the answer is what the user sees. Markers plus a definitions block are the research shape's existing grammar and `CitationLint`'s; auto-capture from the fetches the model already makes removes the need for a citing tool at `cited` / `grounded`. Tools appear only where there is real work to do (`ProofCheck`) or a question to answer (`ProofCheckers`, `ProvabilityPreflight`).
- **Lean 4 as the only formal checker.** Rejected: it requires Docker, a Mathlib-equipped image is multi-gigabyte, and most theorem-shaped claims a harness makes are finite or arithmetic. The `builtin` certificate checker makes `proven` reachable with no sandbox at all; `smt` covers the arithmetic middle; `lean4` is there for the rest, and all three sit behind one interface.
- **Making `level` optimizable.** Rejected: the optimizer is graded by the gate, so letting it move the floor is letting it blind its critic — the same reason `watchme.*` and `learning.sources` are excluded.
- **A new `TrustOrigin` for proofs.** Rejected: there is no new ingestion boundary (§10); inventing an origin with nothing crossing it would mislabel the fabric.
- **A gate built on hooks (`post-model`).** Rejected for the reasons watch-me's §11 gives: hooks are trigger-only lifecycle points that shell out, cannot carry the turn's evidence, and would put user-configurable commands in the middle of a verdict. The in-process seam the judge already uses is the data plane.
- **Default-on at `cited`.** Rejected for 0.8.0: a footer and a retry ladder on every existing harness is a behaviour change the roadmap did not sanction, and the right first default is the researcher template. Revisit with field data from `provability audit`.

## 17. Decisions for owner sign-off

1. **Rung names** `cited | grounded | checked | proven` — four adjectives, one floor, no claim-kind taxonomy in the spec (claim kinds are handled by evidence kinds, §2).
2. **`sources.resolve` default `off`** — a gate-time HEAD adds latency and an egress per source; opt-in.
3. **`sources.bibliographic` default `false`** — "an article reference" means a locatable one; free-text references are accepted only by choice.
4. **`proven` ships `builtin` + `smt` fully and `lean4` as "available, image not curated by default"** — the adapter and pre-scan land; the Mathlib image is a `formal.image` override. *(As built: a Mathlib-free `lean4` image is curated after all, `ghcr.io/crewhaus/sandbox-lean4`, because no suitable upstream image exists; Mathlib stays an override.)*
5. **Channel footer default `footer`** — one line; teams that object set `render: none`.
6. **`continuity.proof` enforcement rides this release** (PR 6) rather than waiting for a 0.3.x patch.

## 18. Top risks (with mitigations)

- **Claim extraction false positives on conversational text** → `threshold < 1.0`, questions/imperatives/code/definitions excluded, `ProvabilityPreflight` shows the model the exact claim list, and the `rungAchieved` grader shows how far short an answer fell rather than a bare fail.
- **Retry loops burning budget** → `max_retries` default 1, every re-run metered through the existing cost path, the waiver judge under `judge_share`, replay bounded by `max_replays`, checkers bounded by `timeout_ms`.
- **Paraphrase misses at `grounded`** → quote mode when the model quotes, coverage window, the opt-in waiver, and the skill's "quote when you can".
- **The formalization gap** → the statement is rendered beside the prose on every surface; the bundle lists assumptions and axioms; no model is asked to vouch for the correspondence (§6.4).
- **Gaming via assumptions or trivial proofs** → counted on every surface, capped, graded, and surfaced by `provability audit`'s gaming signals; never silently excused.
- **The four-copies-to-one refactor (PR 2)** → provability-less bundles byte-diff-pinned; judged bundles behaviour-pinned by the existing evaluation and judge-metering suites; the PR ships first so every later PR builds on one root.
- **Sandbox availability** → `builtin` needs nothing; `smt` / `lean4` degrade to "unavailable" in `ProofCheckers` and the lint says so at compile time; a verifier that throws fails open with an `unverified` verdict the footer shows.
- **Evidence TTL** → excerpts frozen into bundles, the `FrozenProof` lesson applied on day one rather than discovered later.
