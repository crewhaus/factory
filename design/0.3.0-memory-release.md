# CrewHaus v0.3.0 — The Memory Release

**Status:** design draft for review → becomes the RFC issue (`.github/ISSUE_TEMPLATE/rfc.yml`) + a ROADMAP v0.3.x amendment + module briefs 292–298 in the docs repo.
**Scope:** goals, plans, focus, working memory, wiki learning, one-knob Thredz, scheduled "dream" consolidation, and honest failure messaging — default-on continuity for every agent-loop harness.
**Companion doc:** [thredz-future-features.md](thredz-future-features.md) — features that belong in the Thredz API in a future update (deliberately **not** on this release's critical path).

This design was produced by surveying the actual codebase (13 subsystem deep-reads with file:line citations), generating three independent architectures (compiler-purist, memory-science, product-DX), and judging them from three lenses (maintainer feasibility, memory-systems quality, product fit). The compiler-purist backbone won 2 of 3 judges; this document is that backbone with the judges' mandated grafts folded in. Every mechanism cites the seam it plugs into.

## 0. Why this release, in one paragraph

Today a CrewHaus harness has a working but *flat* memory: an append-only BM25 fact store reachable only from the cli shape, transcript-replay resume, in-process todos that die with the process, compaction that silently deletes the middle of a conversation, and failure messaging that renders an out-of-credit account as "agent exited." The 2026 evidence base is unambiguous: production-grade agent memory is a **tiered, externalized, provenance-carrying hybrid stack** — working memory organized around subgoals, episodic facts with confidence and forgetting, semantic knowledge in an updatable wiki, consolidation on a schedule, and retrieval quality treated as the main lever. v0.3.0 builds exactly that, local-first, with Thredz as a one-argument drop-in backend.

### The motivating failure (the release's acceptance test)

A harness-creator conversation: the model asked a clarifying question, the user answered, and later the model **asked the same question again** — the answer had lived only in the middle of message history, where `compaction-snip` deletes outright (keep-head-4/keep-tail-20, `compaction-snip/src/index.ts:25`) and `autoCompact` replaces everything with an unverified ≤4096-token summary (`compaction-autocompact/src/index.ts:43`). A major first-message requirement was dropped, and the run then died on token exhaustion with nothing persisted. Root causes, all verified in the survey:

1. No requirements ledger — user-stated requirements live *only* in message history.
2. No protected-content mechanism in compaction; the curator is spec-plumbed but wired to nothing.
3. No plan/goal/focus artifact survives the process (`tool-todo` is module-level state, `tool-todo/src/index.ts:34`).
4. `crewhaus init --interactive` is single-shot with a **forced** `emit_spec` tool choice (`apps/cli/src/index.ts:3417`) — it literally cannot ask a clarifying question, and extra stdin lines are discarded.
5. Terminal failures throw a bare `RuntimeError` with no class, no structured event, no coded exit.

v0.3.0 is done when this scenario is **un-reproducible even when the model misbehaves** — the fixes below are deterministic infrastructure first, model discipline second.

## 1. Design stance (three ruling principles)

1. **One composition root instead of N copies of codegen.** `renderMemory` exists only in target-cli (`target-cli/src/index.ts:625-680`); the "keep in sync" mirrors in other emitters are fiction. All memory/continuity/wiki/dream/thredz wiring moves into **`@crewhaus/memory-service`**, and every emitter's codegen collapses to one stable call: `const mem = await wireMemory(IR_FRAGMENT, { catalog, mcpHost, cwd })`. Emitters stay dumb (typed IR in, one line out — Pillar 1); runtime-core stays store-free (injected closures via `RunChatLoopOptions`, the #53 pattern). This also closes the module catalog's #2 critical-path unbuilt module, `memory-service` (MODULE-CATALOG-STATUS.md:208).
2. **Deterministic before model-driven.** The ledger is verbatim externalization + re-injection (zero model trust). Proof is reference-checking against the append-only event log (zero model trust). Model synthesis (dream, wiki writing) is layered on top: optional, budget-capped, evidence-linked, and always acting through normal audited tools.
3. **Absent = byte-identical, with one sanctioned exception.** Every new block follows the spread-return-`{}` lowering discipline (`compiler/src/index.ts:813-827` template). The exception is `continuity:`, default-ON per product goal 1. `continuity: false` restores prior bundle bytes exactly, pinned by a byte-diff smoke test. This is the release's one pre-1.0 behavior change (ROADMAP.md:9 sanctions it).

## 2. Goal 1 — Continuity: focus, plans, goals, proof, pickup

### 2.1 The `continuity:` block (new, top-level, default-on)

Carried on the agent-loop shapes — **cli, channel, managed, research, crew** (emit-wired in 0.3.0) and **workflow, batch, voice, browser** (spec-carried; emitters print the 0.2.3-convention comment `// note: continuity configured but ignored on <shape> in 0.3.0`). Deliberately NOT added to graph/pipeline/eval/onchain/onchain-game: the strict union rejects it loudly, which beats silent dead config.

```yaml
continuity: true            # boolean shorthand; this is the default even when absent
continuity:
  enabled: true
  plan: true                # plans/goals/todos persistence + Plan*/Goal* tools
  proof: ladder             # ladder (default) | require | off — see 2.4
  ledger: true              # verbatim requirements ledger (deterministic; see 2.3)
  handoff: true             # teardown handoff.md + session-start pickup block
  scope: auto               # auto | spec | session — see 2.7 (channel/managed scoping)
  focusMaxChars: 4096       # hard cap on the mutable tail block (OPTIMIZABLE)
```

### 2.2 Storage: the Continuity Store (`@crewhaus/continuity-store`)

Human-readable, user-clearable artifacts under `.crewhaus/state/<specName>/` (tenant-fenced when a tenant context is present — same path-fencing rules session-store already enforces, `session-store/src/index.ts:69-71`):

```
.crewhaus/state/<spec>/
  focus.md                  # marker-gated (<!-- crewhaus:focus -->), capped at focusMaxChars
  plans/plan-NNNN-<slug>.md # YAML frontmatter + numbered steps with proof refs
  goals.yaml                # {id, title, status, target?, current?, unit?} — local mirror of Thredz goals
  handoff.md                # deterministic teardown summary (no model call)
  .lock                     # advisory single-writer lock (see 8.6)
```

`focus.md` holds: current focus, the **requirements ledger** (`REQ-nnn` entries, verbatim quotes with `(user, sess_…, turn N)` attribution, status `open|confirmed|dropped`), the active plan pointer, and next actions. Plan steps carry a status from the proof ladder (2.4) and, when proven, `proof: tu_…` toolUseId references. `handoff.md` is rebuilt deterministically at teardown (the `summarizeSession` reducer precedent, `session-store/src/index.ts:375-460`): open steps, next actions, unresolved REQs, last session id.

`TodoWrite` is **kept** (retiring it changes every recompiled harness's tool surface — a compat break the goals don't require) but is re-backed by the plan store: todos become working-tier steps of the active plan, so two sessions or a sub-agent no longer clobber a module-level list. Post-1.0 we can consider folding it away.

### 2.3 The requirements ledger — the deterministic fix for the motivating failure

Two runtime-core changes, both model-trust-free:

1. **`compaction.preserve_user_messages` (new knob, default `true`):** before `snip` drops middle messages and before `autoCompact` replaces history, every USER message about to be evicted is written **verbatim** to the session event log as a new `context_evicted` event kind and appended to the in-run requirements ledger (16KB cap, oldest-first eviction with a `[ledger truncated]` marker — user messages are small).
2. The ledger renders as `<requirements_ledger>` in the **mutable tail region** (2.5), re-injected on every model call. Requirements therefore survive any number of compactions *regardless of what the summary says*. `--resume` rebuilds the ledger from `context_evicted` + replayed user events.

Layered on top (model discipline, from the product-DX design): the `continuity` default skill instructs the model to pin requirements as structured `REQ-nnn` entries in `focus.md` the moment the user states or answers something — quote verbatim, never paraphrase, check the ledger before asking anything. The compaction summarizer's prompt also receives the ledger so summaries are anchored — but correctness never depends on the summary. Additionally, the compaction event now persists the **summary text + before/after provenance** into the event log (today it records counts only, `runtime-core/src/index.ts:3114`), so post-mortems and verifiers have something to check.

**MemGPT-style paging (episodic externalization):** evicted content is not only user messages. On every snip/autocompact, evicted assistant conclusions and tool findings are folded into a provenance-stamped episodic record (`context_evicted` events are readable by the recall path), so `Recall` can page dropped context back on demand instead of it surviving only in the raw JSONL that nothing searches.

### 2.4 Proof of action: the claimed → proven ladder

The event log already records every `tool_use` (full input) and `tool_result` (full output, `isError`) verbatim (`runtime-core/src/index.ts:1880,1895`), plus hash-chained justification/egress audit records — a near-ready proof substrate. What's missing is the claim→evidence link. v0.3.0 adds it as a **status ladder**, not a binary gate:

- Plan steps and goals have status `open → in_progress → claimed → proven`.
- The model may always record progress as **claimed** — zero friction, no gaming pressure, no legitimate no-tool conclusion blocked.
- The **proven** transition is machine-checked: `PlanComplete({step, evidence: [{toolUseId}]})` resolves each id against the session event log — including child sessions by walking `sub_agent_start/end` brackets — and rejects ids that are missing or whose `tool_result` has `isError: true`. The error text teaches: `no verified evidence for tu_…: run the action first, then complete the step with its toolUseId.`
- `handoff.md` and `/plan` render claimed vs proven distinctly, so "the model says it did X" and "the log proves X ran" are never conflated. This is the *bias toward action*: narration can never produce a ✓.
- New additive event kinds `plan_update`, `goal_update`, `action_proof {step, toolUseId, verdict}` (event-log readers skip unknown kinds by design, `event-log/src/index.ts:36-127`).
- `continuity.proof: require` (used by `crewhaus init` templates) refuses plan completion below `proven`; `off` disables verification. The lowered default is the ladder.

**Proof-evidence lifetime (judge-mandated fix all three designs missed):** session JSONLs are TTL-evicted at 30 days, which would silently degrade every `proven` to unverifiable. Two mechanisms close this: (a) any session cited by a live plan step, goal, wiki article, or fact provenance record gets an automatic **retention pin** (`.crewhaus/retention.json`, the existing pin mechanism); (b) the dream pass **freezes a proof excerpt** — `{toolName, inputHash, resultDigest}` — into the citing record before eviction can occur, so evidence outlives the transcript.

- Auto-capture provenance: captured facts gain `provenance: {sessionId, toolUseIds?}`; tool-grounded facts rank above pure-text claims at recall (write-path governance).

### 2.5 The mutable tail region (fixes frozen systemBlocks, blocker g)

`systemBlocks` stays frozen and cache-marked exactly as today (`runtime-core/src/index.ts:1689-1776`). New: runtime-core appends a **volatile tail block array AFTER the cache marker**, rebuilt per model call from `<current_plan>`, `<requirements_ledger>`, and `<recalled_context>` (mid-session recall refresh, §3.4). Because it sits after the marker, edits never bust the cached prefix — they re-tokenize only the tail (hard-capped at `focusMaxChars`, enforced in code). `prompt-cache-manager.manage()` gains a `volatile: true` flag it skips when marking (one-line change at `prompt-cache-manager/src/index.ts:100-107`), plus a **dedicated cache-marker regression test** asserting the tail sits after the marker (a bug here silently busts the cache every turn and multiplies cost).

Refresh path: `PlanUpdate`'s execute sets `plan.dirty` in the per-run `_runState` state-store (`runtime-core/src/index.ts:1613` — finally getting its first consumer); the loop re-reads before the next model call.

New `RunChatLoopOptions.continuity` seam (inverted DI, exactly like `opts.memory` at :607-617; closures constructed by memory-service, runtime-core dependency-free):

```ts
continuity?: {
  loadPlan(): Promise<string | null>;                 // rendered <current_plan> tail content
  onPlanDirty?: () => Promise<string | null>;          // re-render after Plan/Goal mutation
  ledger?: boolean;                                    // context_evicted externalization + reinjection
  verifyProof(ref: ProofRef): Promise<ProofVerdict>;   // event-log check for the proven transition
  onHandoff?(input: HandoffInput): Promise<void>;      // deterministic teardown write
}
```

**Also fixed while we're here (dead wiring the tail depends on):** `promptCacheLastRotatedAt` is currently never threaded or persisted, so every run force-rotates at boot (`runtime-core/src/index.ts:903-908,1783-1804`). The continuity store persists `rotatedAt` per harness and a `cache_rotation` trace event is published — the tail-block cost math assumes a stable cached prefix, so its bookkeeping must actually work.

### 2.6 Default skills and commands (default-on, overridable, clearable)

Zero SKILL.md files ship today and `pluginDirs` is dead (`skills-registry/src/index.ts:88-92`). Default skills are **embedded at compile time** (`@crewhaus/default-skills` exports bodies as string constants; the target-claude-plugin `renderSkill` precedent, `target-claude-plugin/src/index.ts:201-227`) so compiled-bundle behavior never depends on the deploy machine's node_modules. They merge at **lowest precedence** — user (`~/.crewhaus/skills`) and project (`<cwd>/.crewhaus/skills`) override by name (the specialization-registry merge pattern). The interpreter path (`crewhaus run`) uses the same package as a runtime builtin root. Bodies are classified at the `skill` TrustOrigin like any skill.

Skills shipped:

1. **`continuity`** — the discipline: read `<current_plan>` first; pin requirements as REQ entries verbatim; keep the plan current via `PlanUpdate`; never mark proven without evidence toolUseIds; bias to action — do the thing and cite the tool result, don't narrate intent; keep handoff accurate before ending. (Proof-of-work is folded in; one skill, one concern from the model's view.)
2. **`learning-loop`** — goal 2 (§3.3); registered when `learning:` is present.
3. **`dream`** — the consolidation playbook consumed by dream ticks; not listed in the interactive prompt.

Built-in slash commands (slash-commands gains builtin + `~/.crewhaus/commands` roots alongside the existing cwd root): `/plan`, `/focus <text>`, `/next`, `/handoff`, `/clear-plan`, `/forget <query>`, `/study`, `/reflect`, `/exam`, `/dream`.

**Clearing story** (trash + undo, never hard-delete):

```
$ crewhaus memory clear --plans
This moves 3 plan files from .crewhaus/state/support-bot/plans/ to .crewhaus/trash/2026-07-13T19-04-12/
(focus, goals, wiki, and facts are untouched; trash is purged after 7 days)
Proceed? [y/N] y
cleared: plans (3 files) · undo: crewhaus memory restore 2026-07-13T19-04-12
```

`crewhaus memory clear --focus|--plans|--goals|--wiki|--facts|--all`, `crewhaus memory restore <ts>`, `crewhaus memory show` (one-screen: focus, open plans, goals, fact count, wiki stats, dream due). Trash purge is a janitor step. The `MemoryClear` tool (model-invokable via `/clear` commands) is destructive + `requireJustification: true`.

### 2.7 Scoping (judge-mandated: channel/managed were undesigned in all three drafts)

`continuity.scope`:
- `spec` — one store per spec (cli default; also what heartbeat ticks want).
- `session` — per-conversation store (channel Q&A daemons: a single global "current focus" across Slack threads is actively wrong).
- `auto` (default) — cli/research/crew → `spec`; channel conversations → `session` with heartbeat ticks reading the `spec` scope; managed → per-tenant `spec` scope, fenced by the tenancy path rules. **All new stores are tenant-fenced on the managed shape** — commingling tenants' plans/wikis in one store is a data-isolation bug, not a gap.

Crew: roles share the `spec`-scoped plan store (the plan IS the coordination surface; `crewMailbox` remains the message channel); every plan/goal event carries `runContext.agentIdentity` for per-role attribution, and lock contention follows §8.6.

### 2.8 Session pickup, session 1 vs session 2

Session 1 of a fresh harness prints:

```
[memory] continuity on — .crewhaus/state/ (focus · plans · goals) · wiki: local · dream: off
[skills] 2 available (continuity, dream)
```

Teardown writes `handoff.md`. Session 2 (plain `crewhaus run`, no flags needed):

```
[memory] resuming — focus: "Ship CSV export" · plan-0001 step 3/6 open (2 proven) · last session 2h ago
```

and the pickup block gives the model focus + open plan + unresolved REQs. `--resume`/`--continue` still replay transcripts and compose with this. A follow-up flag `continuity.resume: handoff` (post-0.3.0) can seed resume from handoff-plus-tail instead of full replay, which today re-pays compaction on every long resume (`replayMessageHistory` rehydrates full pre-compaction history).

### 2.9 The harness creator, rebuilt (the scene of the crime)

`crewhaus init --interactive` becomes a real multi-turn conversation on `runChatLoop` (persisted session, resumable) instead of the single-shot forced `emit_spec` call. The interviewer gets two tools — `ask_user` and `emit_spec` — with **no forced toolChoice**. Its skill mandates: (turn 1) extract every requirement from the opening message into REQ entries and **echo them back** ("Got it. Requirements so far: REQ-001 …; open questions: …"); (each answer) confirm REQs, never re-ask anything with status `confirmed`; (before emit_spec) verify each REQ maps to a spec field and list the mapping. If the run dies mid-conversation (tokens, funding), the FailureReport prints, the session + ledger are on disk, and `crewhaus init --interactive --resume` restarts with "Resuming: 4 requirements confirmed, 1 open question (REQ-002: …)" — no work redone. Combined with §2.3, the motivating failure is closed from both ends: the generic mechanism and the specific flow.

## 3. Goal 2 — Continual learning: local wiki + the learning-loop skill

### 3.1 `@crewhaus/wiki-store` — the update-in-place semantic tier

What the append-only memory-store cannot be (`memory-store/src/index.ts:47-56`, unbounded-growth TODO #53 F7):

```
.crewhaus/wiki/<spec>/
  articles/<slug>.md        # YAML frontmatter + markdown body
  versions/<slug>/<n>.md    # immutable prior versions (supersede, never delete — Theanine)
  index.json                # slug -> {title, tags, confidence, verified, version, updatedAt, links[]}
  .lock
```

Frontmatter: `slug, title, tags[], confidence (0–1), verified, version, sources[], supersedes?, createdBy {sessionId, agentIdentity}`. Writes carry the expected `version`; conflicts return a stale-version error — the **same contract as Thredz PATCH**, so skills behave identically on both backends.

```ts
interface WikiStore {
  recall(query: string, k: number): Promise<WikiHit[]>;
  search(query: string): Promise<WikiRef[]>;
  get(slug: string): Promise<WikiArticle | null>;
  write(input: WikiWrite): Promise<{slug, version}>;   // upsert; optimistic version check
  list(opts: {staleFirst?, tags?, status?}): Promise<WikiRef[]>;
  related(slug: string): Promise<WikiRef[]>;
  setSignals(slug, {verified?, confidence?}): Promise<void>;
  stats(): Promise<WikiStats>;
}
```

**Retrieval (the evidence base's strongest lever, applied for real):**
- Hybrid BM25 + embeddings with reciprocal-rank fusion, **default-on** with the `mock/` embedder as the offline fallback (`embedder` factory grammar, `embedder/src/index.ts:254-323`) — the orphaned embedder/vector-store stack finally connects to memory. Chunks carry contextual headers (title + tags prefixed) per the contextual-retrieval evidence.
- **One-hop link-graph expansion** (judge-mandated — otherwise the `[[wikilink]]` graph is a display feature): retrieve top-k, pull linked neighbors from `index.json`, re-rank the union. This is the cheap version of the GraphRAG/HippoRAG mechanism and the follow-up path to more.
- The same hybrid ranking applies to the **fact store** (memory-store recall), not just the wiki — leaving facts BM25-only would reproduce the flat-store status quo.

### 3.2 `@crewhaus/tool-wiki` — one tool vocabulary for both backends

RegisteredTools over WikiStore with **exactly thredz-mcp's tool names and schemas**: `wiki_recall`, `wiki_search`, `wiki_semantic_search`, `wiki_get`, `wiki_write`, `wiki_list`, `wiki_related`, `wiki_set_signals`, `wiki_stats`, `log_knowledge_gap` (locally: writes a `gap`-tagged goal into the plan store). Flags: `wiki_write`/`wiki_set_signals` destructive + `requireJustification: true` (spec-overridable via `tool_config`); `log_knowledge_gap` sideEffect audit-and-allow; the rest readOnly. Recalled bodies are classified at the new **`memory` TrustOrigin** and lineage-tagged (the skills-registry two-site pattern).

When `backend: thredz`, local tools are not registered; the synthesized Thredz MCP server's tools register **with a prefix-stripping alias** — a small additive `toolAliases` feature in tool-mcp mapping `thredz__wiki_recall → wiki_recall` (still scope `external` + ioCapability `network` + boundary-classified). One skill vocabulary, one set of permission rules and `tool_config` entries, both backends. `assertToolScopesStrict` gets the canonical names vetted (`compiler/src/index.ts:182-199`). Compile-time `{{…}}` substitution is retained **only** for domain/curriculum templating in the learning skill, not for tool names.

### 3.3 The `learning:` block and skill (the expert demo, productized)

```yaml
learning:
  enabled: true
  domain: "specialty coffee extraction science"
  curriculum: curriculum.md            # optional, agent-editable checkbox ladder
  sources: ["sca.coffee", "*.edu"]     # allowlist hints (NOT optimizable — security)
  exam: { dataset: eval/dataset.jsonl, graders: eval/graders.yaml }
```

`learning:` implies `memory.wiki.enabled: true` (CompilerError if explicitly disabled) and registers the `learning-loop` skill with domain/curriculum substituted at compile time. The skill is the expert demo's four-mode loop, de-hacked:

- **ANSWER** — `wiki_recall` first, cite slugs, never bluff; unsure → `log_knowledge_gap`.
- **STUDY** — pick by gaps → curriculum rung → frontier; fan out researcher sub-agents (now memory-threaded, §7.1); commit only cited, confidence-scored `wiki_write` upserts. Write-path governance is enforced deterministically: when `learning.enabled`, `wiki_write` **rejects bodies without a `## Sources` section** (what was prompt-only in the demo).
- **REFLECT** — `wiki_list` stale-first + `wiki_related` reconcile + `wiki_set_signals`; supersede, never delete.
- **EXAM** — `/exam` invokes the eval library directly on the interpreter path (no agent-shells-to-`crewhaus` hack); compiled bundles keep the documented Bash-allowlist pattern. Failures become logged gaps; new knowledge earns new questions.

The expert demo starter is rewritten to ~30 lines (`learning:` + `thredz:` + domain files) — the migration proof that goal 2 is genuinely pluggable.

### 3.4 Fact-store upgrades + subgoal-conditioned recall

- Additive JSONL fields on `.crewhaus/memories/<spec>.jsonl`: `expiresAt` (from new `memory.ttl`), `supersededBy`, `provenance {sessionId, evidence?: toolUseId[]}`, `schemaVersion`. Old readers skip unknown fields; `crewhaus migrate memories` (migration-runner) backfills where derivable and stamps `.crewhaus/meta.json`.
- New APIs: `forget(id|query)` (supersede tombstone lines — the file stays append-only; recall filters superseded/expired), `sweep()` (TTL). New tool **`MemoryForget`** (destructive + requireJustification).
- **Subgoal-conditioned recall (HiAgent):** recall queries concatenate the active plan/focus subgoal titles; the `<recalled_context>` tail block refreshes when the active subgoal changes — recall is no longer session-start-only.

## 4. Goal 3 — Thredz: one argument

### 4.1 Spec

```yaml
thredz: $THREDZ_API_KEY          # string shorthand — THE one argument
# or
thredz:
  api_key: $THREDZ_API_KEY       # required; lowerCredential → IrSecretRef (fail-fast on non-$UPPER_SNAKE)
  base_url: https://thredz.crewhaus.ai/api
  agent_name: my-expert          # optional; idempotent agent_register at boot (stable a2a handle)
  visibility: private            # DEFAULT private — overrides Thredz's shared-by-default foot-gun
  tools: [wiki, goals]           # groups: wiki | goals | messaging (default [wiki, goals])
  command: bun                   # optional escape hatch for vendored/self-hosted servers
  args: [./thredz-mcp/server.ts]
```

`lowerThredz` produces `IrThredz {apiKey: IrSecretRef, baseUrl?, agentName?, visibility, tools}` and **synthesizes** an `IrMcpServers` entry `thredz: {transport: stdio, command: "npx", args: ["-y", "thredz-mcp@0.2.0"(exact pin)], env: {THREDZ_API_KEY: {kind:"env",…}}, toolAliases: {…}}`. `memory.backend` defaults to `thredz` when the block is present. A user-declared `mcp_servers.thredz` alongside `thredz:` is a CompilerError (one owner). `collectSecretRefs` lists THREDZ_API_KEY in the generated README automatically once MCP env carries IrSecretRef. All of this lives in `lower()`, **not** ir-passes — passes are opt-in and skipped on the plain compile path (`apps/cli/src/index.ts:949-952`).

### 4.2 The MCP secret fix (blocker a — the release's most load-bearing compiler change)

Verified: there is **no delivery path for any secret into any MCP child process today** — `lowerMcpServers` copies env/headers verbatim into the bundle (`compiler/src/index.ts:245-265`), and the MCP SDK's child env allowlist drops arbitrary keys (the expert demo survives only via Bun's cwd `.env` auto-load, which `npx` breaks). Fixed as a general capability:

1. **IR (breaking, pre-1.0 sanctioned):** `IrMcpStdioConfig.env` / `IrMcpSseConfig.headers` become `Record<string, IrSecretRef>`.
2. **Compiler:** every env/header value routes through `lowerSecret` (permissive; plain strings stay literals), upgraded to `lowerCredential` fail-fast for key-shaped fields (`*_KEY`/`*_TOKEN`/`Authorization`).
3. **Runtime:** `resolveSecretRef(ref)` in mcp-host — `kind:'env'` resolves via **secrets-manager's** env backend (vault/file backends and rotation work for free), failing fast at boot with a ConfigError naming the variable.
4. **mcp-host client:** stdio transport passes `{...getDefaultEnvironment(), ...resolvedEnv}` so explicit env survives the SDK allowlist.

### 4.3 Runtime backend flip — one connection, one vocabulary

When `ir.thredz` is present, `wireMemory` constructs:

- **ThredzWikiStore / ThredzMemoryStore** implemented by calling the thredz MCP tools **programmatically through the already-connected McpHost client** (`McpClient.callTool`, `mcp-host/src/client.ts:237`) — no parallel HTTP client, one authenticated channel, one error-mapping choke point, and tool-mcp's boundary classification applies to programmatic reads too. `remember`/`recall` map to private wiki articles tagged `crewhaus-memory` (the Thredz memory guide's own recommendation).
- **Goals** map to Thredz goals/tasks via the new `goal_*`/`task_*` MCP tools (external PR, §4.5). **Focus + ledger + dream state stay local always** — session-scoped working state has no server-side primitive yet (future-features doc).
- **Redact-on-write (judge-mandated):** every body leaving the machine for Thredz (`wiki_write`, capture, handoff mirror) first passes the existing knowledge-sync redaction pipeline (PII + credential redaction with drop-if-secret-remains) plus a dataLineage credential-token check — `visibility: private` governs who can read, not what secret content leaves the machine.
- **Visibility enforcement (judge-verified hole):** thredz-mcp's `wiki_write` currently sends **no visibility field** and the API defaults to globally-shared. Factory injects/enforces `visibility` deterministically on the write path (and the thredz-mcp PR adds the parameter + `THREDZ_DEFAULT_VISIBILITY`); this is never left to skill-body reminders.

### 4.4 Failure semantics: degrade vs halt

**Memory-backend failures degrade; provider failures halt.** A lapsed Thredz subscription must never kill a local-first harness:

- Missing key at boot: `crewhaus: THREDZ_API_KEY is not set (required by thredz: in support-bot.yaml) · Get a key: https://thredz.crewhaus.ai → Account → API keys (exit 21)`.
- Disabled key (403 "API key is disabled" — billing lapse): boot probe warns; per-call tool errors say `Thredz: this API key is disabled — usually a lapsed subscription. Fix billing at …/account/billing. The harness keeps running; wiki/goals are unavailable until the key is re-enabled.`
- Quota (402): `Thredz plan limit reached (goals: 3/3 on the free plan) — the write was not saved. Upgrade: …/pricing.`
- 429: honor `Retry-After`, 2 retries, then surface with the wait time.
- `crewhaus doctor` gains a live Thredz probe (stats call → plan + wiki grant reported).

### 4.5 External dependency, explicitly sequenced (thredz-mcp v0.2.0)

PRs on that repo, gating factory's Thredz PR: (1) goals/tasks tools (`goal_list/get/write/update`, `task_list/complete` — generalizing `log_knowledge_gap`, normalizing the single-element-array quirk and non-idempotent increase); (2) **`visibility` parameter on `wiki_write`** + `THREDZ_DEFAULT_VISIBILITY`; (3) `present()` error mapping (401/402/403-disabled/429+Retry-After → clear text); (4) serverInfo version read from package.json; (5) `EXPECTED_TOOLS` smoke update; (6) tag v0.2.0 + NPM_TOKEN publish with provenance. ## 6. Goal 5 — Dream: scheduled consolidation

### 6.1 Spec

```yaml
dream:                      # nested under memory: (memory.dream) — one shared zod object
  every: 24h                # heartbeat duration grammar, lowered via parseDurationToMs
  mode: full                # deterministic | full
  budget_usd: 0.50          # model-phase cap (OPTIMIZABLE); 0 = deterministic only
  instructions: |           # optional playbook override; default = dream skill body
```

### 6.2 Mechanism (`@crewhaus/dream-engine`) — consolidation on a schedule, not every turn

Phase 1 — **deterministic** (always, idempotent, no model): summarize-unindexed-sessions (sessions-index); fact dedupe + supersede (closing the #53 F7 unbounded-growth TODO); fact TTL/decay sweep (staleness flags, never silent deletion); wiki staleness scan; **proof-excerpt freezing + retention pins** (§2.4); focus/handoff refresh from open plans; trash purge; episodic→semantic **promotion flags** (facts recalled ≥N times or corroborated across sessions become wiki-draft candidates).

Phase 2 — **model synthesis** (`mode: full`, only if `budget_usd > 0`): ONE bounded fresh session (`sessionTarget: 'dream'`) seeded with the dream skill + phase-1 findings; it merges/splits wiki articles (versioned — reversible), adjusts confidence signals, promotes flagged facts into cited wiki drafts, logs gaps, rewrites next-actions. **Every mutation goes through the normal registered tools** (`wiki_write`, `wiki_set_signals`, `MemoryForget`, `PlanUpdate`) — same requireJustification/audit path, and every synthesis action leaves tool_use/tool_result proof. Dream **refuses to run the model phase with an unpriced model** (cost-tracker `pricingMisses` makes budget caps silent no-ops otherwise, `runtime-core/src/index.ts:926-929`). Output content is classified at the `memory` TrustOrigin before any future injection.

State: `.crewhaus/dream/<spec>/state.json {lastRunAt, lastOutcome, lastEvidence: toolUseId[]}` + a `dream_run` event kind — proof the dream actually ran. **Mutual exclusion:** dream runs are idempotency-keyed on the schedule window via durable-execution's `withIdempotency`, so a daemon janitor tick, a GH-Actions cron, and a cli catch-up can never double-fire, including under `fleet run` parallelism.

### 6.3 Triggers (blocker d: no janitor on the cli shape)

- **Daemons** (channel/managed/batch): `createJanitor` gains a **pluggable step registry** (replacing the closed union at `janitor.ts:85-88`); the dream step due-checks `state.json` inside the existing boot+hourly tick — restart-safe, catch-up for free, `CREWHAUS_DREAM=0` / `CREWHAUS_DREAM_INTERVAL_MS` env knobs per convention.
- **cli shape**: (1) **boot-time catch-up runs the deterministic phase only** — sub-second, zero spend — and prints `[dream] overdue — deterministic pass done; run 'crewhaus dream' for full consolidation`. Unattended model spend is never a side effect of starting or ending an interactive session. (2) `crewhaus dream run|status|init` — cron-safe verbs following the security-digest conventions; `dream init` scaffolds a GH-Actions cron (odd-minute convention) via ci-scaffold. (3) `/dream` runs the model phase in-session, budget-capped.
- Heartbeat is untouched (channel keeps both: heartbeat is liveness, dream is consolidation).

## 7. Cross-cutting

### 7.1 Sub-agents (blocker c)

`spawnSubAgent` (`sub-agent-spawner/src/index.ts:96-111`) threads four new option groups from the parent bridge: `memory` (**recall on, capture off** — children read, the parent owns writes), `skills` (children finally see the skills prompt block, not just the inherited Skill tool), `failureTaxonomy`, and a **read-only** `continuity.loadPlan`. Parent auto-capture and proof resolution walk `sub_agent_start/end` brackets into child session JSONLs (with per-child read caps for research fan-outs) — researcher findings finally reach memory with `provenance: subagent:<id>`, and child toolUseIds are valid proof. Child failures are classified before stringifying: a billing/auth failure inside a researcher re-throws as a FailureReport instead of dissolving into a `[sub-agent error]` string.

### 7.2 Eval, optimizer, and fleet isolation (judge-mandated)

Runs under `crewhaus eval`, the flywheel, and the optimizer get **ephemeral/namespaced `.crewhaus` state** — plan/focus/handoff written by sample N must not leak into sample N+1 (Pillar 2 assumes spec patches are the only cross-run channel). `fleet run` gets an integration test for concurrent store access.

### 7.3 Memory-quality evals (evaluate end states, not answers)

New graders in the grader registry: **`end_state`** (assertions over `.crewhaus/` after a run — did the plan advance, was the handoff written), **`proof_coverage`** (fraction of proven steps whose evidence still resolves), **`recall_precision`** (seeded store + mock embedder, offline), **`contradiction_rate`** (wiki reconcile checks). These gate the default-on flip: proof gating and ledger behavior are measured before 0.3.0 ships, and a before/after **token-overhead eval** publishes the per-shape cost table for the default-on tail (~1–3KB/turn, hard-capped).

### 7.4 Security fabric

- New TrustOrigin **`memory`** (one origin, not two): recalled wiki/fact content and dream synthesis — classified + lineage-tagged at injection, default policy block-tier like `skill`. Plan/ledger content is user-authored (origin `user`); Thredz reads keep origin `mcp`.
- New tools: `wiki_write`, `wiki_set_signals`, `MemoryForget`, `MemoryClear` are destructive + `requireJustification: true`; `FocusWrite`/`PlanUpdate` are destructive + audit-and-allow (a judge call per routine plan update would drown the loop; justification is reserved for drops/deletes).
- Redact-on-write for all Thredz-bound bodies (§4.3).
- Skill frontmatter `tools` allowlists remain unenforced in 0.3.0 (noted follow-up: catalog narrowing while a skill is active).

### 7.5 OPTIMIZABLE_PATHS (Pillar 2, each with a comment-preserving round-trip test)

Added: `memory.recallK` (newly registered), `memory.autoCaptureThreshold`, `memory.wiki.recallK`, `memory.dream.budget_usd`, `continuity.focusMaxChars`. **Excluded deliberately:** `thredz.*` (credentials), `memory.backend`, `continuity.proof`, `compaction.preserve_user_messages` (safety), `memory.dream.every` (side-effecting schedule), `learning.sources` (allowlist = security).

### 7.6 Concurrency policy (judge-mandated: asserted ≠ designed)

Update-in-place stores (`wiki`, `state`) use advisory `.lock` files with a defined policy: wait up to 2s → steal if lock mtime >30s stale (log a `lock_stolen` warning) → fail with a clear error naming the holder pid. Writes are tmp+rename atomic; `index.json` rebuilds are crash-safe (rebuildable from articles). Append-only stores keep sidestepping locking. Fleet-run and sub-agent contention are integration-tested.

## 14. Resolved decisions (owner sign-off 2026-07-13)

5. **Channel scoping (`scope: auto`), validated against Thredz:** Thredz models messaging as one thread per agent *pair* with per-key tenant isolation — there is no per-end-user conversation segmentation for a single agent serving many humans, goals are **key-scoped**, and plan quotas are tight (3 goals on free).
