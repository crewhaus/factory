# Byte-restore pins for v0.3.0's default-on continuity (PR 11)

These fixtures are the release's compat contract (design §12): **recompiles
differ only via default-on continuity, and `continuity: false` restores prior
bundle bytes exactly.**

- `<key>.spec.yaml` — the pinned spec.
- `<key>.<file>.txt` — the bundle bytes that spec produced on the 0.3.0 train
  **immediately before PR 11** (the `feat/030-pr10-memory-service` tip — the
  last commit where the spec surface had no `continuity:` key). Relative to
  released `main`, those bytes additionally include PR 1–10's own documented
  deltas (Goal-6 catch wrappers, MCP secret refs, the PR 10 wireMemory
  refactor); PR 11's contract is that it adds NOTHING beyond continuity.
- `cli-plain.agent.default-on.txt` — the pinned NEW output: the same cli spec
  with continuity absent (= default-on), generated by PR 11 itself.

`continuity-byte-restore.test.ts` compiles each spec with `continuity: false`
appended (and, for the daemon shapes, the `memory:` block stripped — memory
became emit-wired on channel/managed/research/crew in 0.3.0, a separate
documented delta) and asserts byte equality with the pins.

## Regenerating

Only regenerate when a LATER release deliberately changes emitted bundles;
never to paper over an accidental diff.

1. `git checkout <the commit these pins should reflect>` (for the 0.3.0
   train: `feat/030-pr10-memory-service`).
2. From `packages/compiler`, run a script that `compile()`s each
   `<key>.spec.yaml` (readme: false) via `./src/index.ts` — **the workspace
   source, not a published `@crewhaus/compiler`** — and writes each bundle
   file to `<key>.<file>.txt`.
3. Return to your branch and re-run the byte-restore test.
